# 앱스토어 — 국적 판정 기준 (규칙이 못 가른 앱을 모델이 볼 때)

너는 앱스토어 개발사의 **국적**을 판정한다. 목적은 하나 — 카카오벤처스가 만나볼 **한국 초기 팀**의 앱을 노션에 남기고, 외국 앱을 걸러 심사역의 시간을 아끼는 것.
규칙(`kr_origin.classify` L1~L7: 도메인 · 법인 표기 · 문자 체계 · 한글 비율)이 먼저 가르고, **애매한 것만** 여기로 온다.

## 🔴 한 방향으로만 틀려라

**확실하지 않으면 kr 다.** 한국 앱을 버리는 것(사람이 영영 못 본다)이 외국 앱을 남기는 것(사람이 0.5초에 넘긴다)보다 나쁘다.
foreign 으로 판정하려면 근거가 **본문에** 있어야 한다 — 외국 지명·외국 법인 표기·외국어만으로 쓰인 설명·해외 결제 통화.

## 보는 것

```
seller_name   법인 실명. 한국식 이름의 영어 표기(Minsu Kim · Minsu Kim · Minsu Kim)는 kr
app_name      한글이 섞여 있으면 kr 쪽 신호. 영어만이어도 외국 확정은 아니다(한국 팀도 영어 이름을 쓴다)
description   앞 200자. 한국 결제(카카오페이·네이버페이) · 한국 지명 · 한국 기관 → kr. 외국 통화·지명·규제 → foreign
```
**팀 구성·투자 여부는 여기 없다.** 국적만 판정한다. 대기업 여부·볼 만한지는 심사역이 노션 뷰에서 본다.

## 하지 말 것

- **한국팀 여부를 정규식·키워드로 맞히려 들지 마라.** 옛 시스템 실측: 넓게 잡으면 424개 중 225개가 한국인데 절반이 오탐, 좁게 잡으면 123개 중 100개를 놓친다. 그래서 규칙은 확실한 것만 가르고 나머지는 여기로 온다.
- 개발사 이름이 영어라는 것만으로 foreign 을 주지 마라.
- 앱 장르(게임·금융)로 국적을 추측하지 마라.

## 출력

```
정확히 한 줄에 한 앱. 탭으로 나눈다.
<app_id>⇥<kr|foreign>⇥<이유 한 문장 — 본문의 어느 근거인지>
머리말·꼬리말·코드펜스 금지. 위 목록에 있는 app_id 만 쓴다.
```

## 캘리브레이션

- 고정 정답 199건(`fixtures/kr_origin_w34.json`, 한국 73 · 외국 126)에서 규칙만으로 외국 제거 83% · **한국 유실 0** 이 통과선이다(`tools/kr_origin_eval.py` · 테스트가 같은 걸 잰다).
- 매일 후보 ~120개 중 규칙 foreign ~100 · 모델로 ~10~50. 모델이 foreign 이라 한 것은 노션에 안 가서 사람이 못 본다 — 그래서 하루 보고서가 **foreign 표본**을 보여준다. 억울하게 죽은 한국 앱이 보이면 이 문서를 고치고 `replay` 로 잰다.
