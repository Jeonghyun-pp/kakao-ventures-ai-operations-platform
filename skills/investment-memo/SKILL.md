# 투심보고서 자동 생성

카카오벤처스 11호 펀드 투심보고서를 무인 생성한다. 이 산출물은 **회사가 주장하는
내용의 요약본이 아니라, 심사역이 미팅·실사에서 캐낸 1차 근거로 뒷받침된 LP용
보고서**여야 한다. IR 덱만 읽고 쓰면 실패한다.

실행 엔진은 MCP 서버(tool 8개) + 계산 도구(`mcp/tools/`) + 섹션 프롬프트
16개다. 이 스킬은 그것들을 정해진 순서로 오케스트레이션한다.

<HARD-GATE>
본문 서술을 시작하기 전에 노션 스타트업 DB에서 해당 회사 페이지를 반드시 찾아
미팅록을 읽는다. 못 찾으면 "노션에 없음"을 확인한 뒤에 진행한다. 예외 없음.

투심보고서의 핵심 근거(고객사 실명, 미팅 수치, 레퍼런스 결론, 투자자 우려와
해소)는 IR 덱에도 웹에도 없고 미팅록에만 있다. 건너뛰면 IR 요약본이 나온다.
</HARD-GATE>

---

## Non-Negotiable Rules
모든 실행에 적용된다. 위반은 재작업의 주 원인이다.

<CRITICAL>
**#1 — 스캔 PDF는 read_image로 본다**: 등기부·주주명부·사업자등록증은 대부분
스캔본이라 텍스트가 0자다. `read_file`이 `[스캔 문서]` 배너를 반환하면 그
페이지를 `read_image`로 직접 보기 전까지 값을 쓰지 않는다. 파일명에서 유추한
값을 사실인 양 쓰면 안 된다.

**#2 — 계산은 코드, 판단은 프롬프트**: IRR·Multiple(`irr_calc.py`), 표 채우기
(`tables_fill.py`), 문체 검사(`style_check.py`)는 결정론이라 코드가 한다. LLM이
암산하면 틀린다. 회수방안 선택·근거·서술은 프롬프트가 한다.

**#3 — 못 찾으면 지어내지 않는다**: 값이 소스에 없으면 `(미확인 — 필요자료)`로
남긴다. 그럴듯한 추정치를 넣으면 심사역이 검증 없이 LP 보고서에 싣는다.

**#4 — 회사 주장과 심사역 판단을 구분한다**: 미팅록에는 둘이 섞여 있다. 회사
주장은 `(2026.04 미팅, 회사 제시)`로, 심사역의 날것 평가("벙벙한 IR")는 옮기지
않고 `투자자 우려와 해소` 형태로 쓴다.

**#5 — 길이가 아니라 밀도로 채운다**: 불릿 하나는 짧게(중앙값 68자), 논거는
충분히(주장→근거→사례→함의를 각각 별도 불릿). save_section이 문체를 자동
검사한다. 완성본은 한 논거를 여러 불릿으로 쪼개 깊게 전개한다.

**#6 — 산출물이 아닌 것만 인풋으로 본다**: 폴더에 완성된 투심보고서가 섞여
있으면 자기 출력을 입력으로 읽는 오염이 생긴다. scan_inputs가 걸러주지만,
`11호 투심보고서_*.docx`는 인풋이 아니다.
</CRITICAL>

## Phase 0: 준비
### 목표
회사명과 인풋 폴더 경로를 확정한다.
### 실행
1. 사용자가 회사명·폴더를 안 주면 묻는다 (예: `~/Downloads/투심보고서/Corpus02`)
2. `scan_inputs(folder)` — 문서를 역할별로 분류하고 산출물을 제외한다
### 게이트
등기부·Term Sheet·Investment Theme·IR덱 중 없는 핵심 자료가 있으면 사용자에게
알리고 진행 여부를 확인한다.

---

## Phase 1: 소스 흡수
### 목표
표와 서술의 모든 근거를 확보한다.
### 실행
1. `read_file`로 각 문서를 읽는다. `[스캔 문서]` 배너가 뜨면 `read_image` (#1)
2. IR 덱은 전 페이지를 열지 않는다 — `get_prompt("21_IR덱읽기")`로 페이지를
   선별해 필요한 것만 `read_image`
3. **노션 미팅록** — `get_prompt("22_노션연동")` 후 스타트업 DB에서 회사 페이지를
   찾아 미팅록·DB 속성(담당자·발굴경위)을 읽는다 (HARD-GATE)
### 포화 조건
문제정의·현황·경쟁우위의 1차 근거(고객사 실명, 미팅 수치)를 확보했는가.
못 했으면 미팅록을 다시 읽는다.

---

## Phase 2: 표 채우기
### 목표
표 8개를 소스에서 채운다. 본문과 별개 경로다.
### 실행
1. `get_prompt("20_표추출")`로 출처 우선순위·자기점검을 로드
2. 등기부(설립일=회사성립연월일)·주주명부·Term Sheet·IR덱(핵심인력)에서 추출
3. `save_tables(tables)` — 값 없는 라벨은 키를 넣지 않는다(법률 보일러플레이트 보존)

---

## Phase 3: 서술 12섹션
### 목표
각 섹션을 확정 근거로 쓰고 문체 검사를 통과한다.
### 실행
섹션마다: `get_prompt(섹션)` → 작성 → `save_section` → 문체 검사 확인.
`❌`가 나오면 고쳐서 다시 저장한다.

**작성 순서 (01_투자포인트는 반드시 마지막 — 전체 종합)**:
```
05a_문제정의 → 05b_가설 → 06a_서비스상세 → 06b_지표 → 07_BM →
08_향후전략및계획 → 09_financial_projection → 10_시장현황및전망 →
11_주요경쟁자 → 12_경쟁우위평가 → 13_investment_analysis → 01_투자포인트
```

**재무 3섹션 특칙**:
- 09 FP: 엑셀에 있으면 추출(지어내지 않음), 없으면만 Top-down/Bottom-up 작성
- 13 Investment Analysis: `irr_calc.py`의 `peer_psr` → `exit_analysis` →
  `format_analysis`로 IRR 계산. 프롬프트가 판단·맥락을 덧붙인다
- FP의 Exit 매출과 IRR의 exit_revenue를 일치시킨다

---

## Phase 4: 생성과 검증
### 목표
docx를 만들고 품질을 확인한다.
### 실행
1. `create_report(회사명, 폴더)` — 표+섹션으로 최종 docx 생성.
   "표 데이터 없음" 경고가 있으면 Phase 2를 건너뛴 것
2. (선택) `python scripts/backtest.py compare 생성본.docx 완성본.docx` —
   완성본이 있으면 논거 커버리지·문체를 측정
### 자기 점검
| # | 검사 |
|---|------|
| 1 | `[작성 필요]`·TBD가 본문에 남았는가 → 채우거나 사유 확인 |
| 2 | 표의 금액·주식수가 원문과 다른가 → 대조 |
| 3 | 미팅록 유래 내용에 시점 표기가 없는가 |
| 4 | IRR·매출 수치가 코드 계산값과 다른가 |
