# IR 덱 읽기 전략

IR 덱은 보통 25~40페이지다. 전 페이지를 이미지로 보면 컨텍스트가 터지고,
텍스트만 읽으면 차트의 수치를 통째로 놓친다. **텍스트로 지도를 먼저 만들고
필요한 페이지만 이미지로 본다.**

표 추출(`20_표추출.md`)과 본문 서술 섹션이 함께 참조한다.

---

<HARD-GATE>
IR 덱 전 페이지를 read_image로 읽지 않는다. 페이지 지도를 만들어 대상 페이지를
고른 뒤에만 이미지를 연다. 예외 없음.

34페이지 덱을 전부 열면 그 뒤 작업에 쓸 컨텍스트가 남지 않는다. 대부분의
페이지는 텍스트만으로 충분하다.
</HARD-GATE>

---

## Phase 1 — 페이지 지도 만들기

`read_file`이 반환한 텍스트는 `--- Page N ---`으로 나뉘어 있다. 각 페이지의
첫 줄(제목)만 훑어 **어느 페이지에 무엇이 있는지** 목록을 만든다.

IR 덱은 페이지마다 영문 섹션명을 헤더에 단다. 이것이 지도의 뼈대다.

```
p10  POSITIONING   경쟁 좌표
p23  TRACTION      검증한 5가지 가설
p29  REVENUE MODEL 축적에서 플랫폼으로
p31  ASK · SEED    Seed 라운드 조건
```

## Phase 2 — 이미지로 볼 페이지 고르기

아래 신호가 있으면 그 페이지는 **텍스트만으로 부족하다**. 이미지를 연다.

| 신호 | 왜 |
|------|-----|
| 페이지 텍스트가 **20자 미만** | 이미지 한 장으로 된 페이지 |
| 제목에 POSITIONING·LANDSCAPE·QUADRANT·MAP | 경쟁 좌표는 위치가 곧 정보라 텍스트로 무너진다 |
| 제목에 TRACTION·METRIC·KPI·GROWTH | 수치가 차트 안에 있어 추출되지 않는다 |
| 제목에 REVENUE·BM·PRICING | 단가·구조가 도식에 들어 있다 |
| 제목에 TEAM·FOUNDER | 인물별 경력이 카드 레이아웃이라 순서가 엉킨다 |
| 텍스트에 숫자는 보이는데 **단위·축·범례가 없다** | 차트 라벨만 추출된 상태 |
| 한글이 `경 쟁 좌 표`처럼 **글자마다 띄어져** 있다 | 디자인 자간 처리. 표·도식일 가능성이 높다 |

**페이지 예산**: 기본 **8페이지 이하**. 넘칠 것 같으면 순서대로 적용한다.

1순위: 표에 직접 들어갈 값이 있는 페이지 (경쟁사, 지표, 팀)
2순위: 본문 섹션의 핵심 근거가 되는 페이지 (문제정의, BM)
3순위: 시장 규모·성장률 차트
최후: 8페이지를 넘겨서라도 필요한 값을 확보한다 — 단, 왜 넘겼는지 남긴다
금지: 예산에 맞추려고 필요한 값을 `(미확인)`으로 처리하는 것

## Phase 3 — 읽은 내용을 수치로 옮기기

<CRITICAL>
**#1 — 차트에서 읽은 수치는 축과 단위를 함께 적는다**: 숫자만 옮기면 나중에
검증이 불가능하다.

나쁜 예: `MAU 900만`
좋은 예: `MAU 30만 → 900만 (2019~2023, ByteDance TikTok Korea 재직 기간)`

**#2 — 덱의 주장과 사실을 구분한다**: IR 덱은 회사가 만든 자료다. 검증된 수치와
회사의 전망을 같은 무게로 옮기면 안 된다. 전망·목표치에는 근거 주체를 명시한다.

나쁜 예: `2028년 매출 68억`
좋은 예: `2028년 매출 68억 (회사 제시 추정)`

**#3 — 도식에서 경쟁사를 읽을 때는 축의 의미까지 옮긴다**: 사분면 차트는 위치가
정보다. 이름만 적으면 그 회사가 왜 그 자리에 있는지가 사라진다.

나쁜 예: `["직접", "Character.ai", "경쟁사"]`
좋은 예: `["1:1 챗 · Tech-first", "Character.ai, 제타", "단일 IP 기반 1:1 대화. Corpus02는 Platform-native × Multi-IP 사분면으로 차별화 (IR 덱 p10)"]`

**#4 — 페이지 번호를 근거로 남긴다**: 표나 본문에 넣을 때 `(IR 덱 p10)` 형식으로
출처를 붙인다. 심사역이 원본을 대조할 수 있어야 한다.
</CRITICAL>

## 표별 후보 페이지

| 채울 곳 | 찾을 페이지 제목 키워드 |
|---------|----------------------|
| 핵심인력 | TEAM, FOUNDER, WHO WE ARE |
| 주요경쟁자 | POSITIONING, LANDSCAPE, COMPETITION, QUADRANT |
| 지식재산권 | IP, PATENT, TECHNOLOGY, MOAT |
| 회사히스토리 | TIMELINE, HISTORY, MILESTONE, TRACTION |
| 임직원 수 | TEAM, ORGANIZATION, HIRING |

해당 페이지가 없으면 그 표는 다른 소스를 찾거나 `(미확인)`으로 둔다.
덱에 없는 내용을 덱에서 읽은 것처럼 쓰지 않는다.

## 자기 점검

| # | 검사 | 심각도 |
|---|------|--------|
| 1 | 전 페이지를 이미지로 열었는가 | ❌ 중단 |
| 2 | 이미지로 연 페이지가 8개를 넘는데 사유를 안 남겼는가 | ⚠️ 사유 기록 |
| 3 | 차트에서 읽은 수치에 단위·기간이 빠졌는가 | ❌ 보완 |
| 4 | 회사 전망치를 검증된 사실처럼 적었는가 | ❌ `(회사 제시)` 표기 |
| 5 | 표·본문에 넣은 덱 유래 값에 페이지 번호가 없는가 | ⚠️ 추가 |
