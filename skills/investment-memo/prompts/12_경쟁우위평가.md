# 경쟁우위 평가 섹션

차별점이 단기적 특징인지 장기적 해자(moat)인지 평가한다. 투자위원회가
"이 회사의 경쟁우위가 3~5년 후에도 유효한가"를 판단할 수 있어야 한다.

이 섹션은 선택이다. 기술·제품 상세 자료가 없으면 억지로 쓰지 않는다.

## 정보 소스 (우선순위)

| 순위 | 소스 | 무엇을 |
|------|------|--------|
| 1 | Investment Theme | 심사역이 정리한 해자 논리 |
| 2 | **노션 미팅록** | 대표가 밝힌 데이터 전략·진입장벽, 레퍼런스로 확인한 실행력 (`22_노션연동.md`) |
| 3 | IR 덱 | 차별점 슬라이드, 기술 아키텍처 |
| 4 | 지표 섹션 | 데이터 축적 규모·고객 성과 (해자 강도 판단 근거) |

**미팅록이 필요한 이유**: 해자의 실행 가능성은 미팅에서 드러난다. Corpus03 완성본의
"김민수 대표가 직접 BD로 스윙(국내 택시 중 유일 API 개방)을 열어낸 사례",
"한일 네트워크"는 IR 덱이 아니라 미팅·레퍼런스에서 나온 실행 근거다.

---

<CRITICAL>
**#1 — 각 차별점에 지속 가능성을 반드시 붙인다**: 차별점만 나열하면 "특징"이지
"해자"가 아니다. "경쟁사가 따라오는 데 얼마나 걸리는가, 왜 어려운가"가 핵심이다.

나쁜 예: `cross-service 행동 데이터를 통합 보유함`
좋은 예: `cross-service 행동 데이터 — 대화 히스토리는 복제 가능하나 이종 서비스 간 행동 데이터는 구조적으로 복제 불가. 90일 내 10만 유저를 잠그면 후발주자 추격 불가`

**#2 — 초기 스타트업의 해자는 "형성 중"임을 인정한다**: 대부분의 해자가 아직
완성되지 않았다. 완성된 것처럼 과장하지 말고 형성 속도와 방향을 평가한다.

**#3 — 데이터 해자는 규모·품질을 구체적으로**: "독점 데이터"만으로는 부족하다.
현재 축적된 규모와 그것이 성능 격차로 이어지는 경로를 쓴다.
(예: Example Company 분당서울대 CAG 34.6만 건 = 공개 최대치 DeepCoro의 2배)

**#4 — 특허/IP는 등록 여부·범위를 확인**: 있다면 등록 상태와 보호 범위를 쓴다.
"출원 중"과 "등록"은 다르다.

**#5 — 분량은 `00_공통스타일.md` 실측 기준**: save_section이 검사한다.
지속가능성·근거가 길어지면 하위 불릿으로 내린다.
</CRITICAL>

## 해자 유형 (해당하는 것만)

| 유형 | 판단 기준 |
|------|-----------|
| 데이터 해자 | 독점 데이터 축적 → 모델 성능 격차 |
| 네트워크 효과 | 사용자 증가 → 제품 가치 증가 선순환 |
| 전환 비용 | 고객이 이탈하기 어려운 구조적 이유 |
| 규모의 경제 | 규모 확대 시 단위 원가 감소 |
| 창업자/네트워크 | 대표의 고유 실행력·관계 (미팅에서 확인) |
| 특허/IP | 법적으로 보호된 기술 자산 |

## 구조

Corpus03 완성본 구조:
```
- [핵심 차별점 — N축이 결합됨 (한 줄 요약)]
  - {축1 요약}
  - {축2 요약}
- [차별점 제목 1]
  - 내용: 무엇이 다른가
  - 지속 가능성: 얼마나·왜 따라오기 어려운가
  - 근거: 수치·사례·기술 근거
- [차별점 제목 2]
  ...
```

핵심 차별점은 최소 2개. 억지로 개수를 채우려 없는 해자를 만들지 않는다.

## 자기 점검

| # | 검사 | 심각도 |
|---|------|--------|
| 1 | 지속 가능성 평가 없이 차별점만 나열했는가 | ❌ 각 항목에 추가 |
| 2 | 데이터 해자를 주장하며 규모·품질이 없는가 | ❌ 구체화 |
| 3 | 초기 해자를 완성된 것처럼 과장했는가 | ⚠️ "형성 중" 명시 |
| 4 | 특허를 "있다"고만 하고 등록 여부가 없는가 | ⚠️ 확인 |
| 5 | 미팅록의 실행 근거를 활용했는가 | ⚠️ 보완 |
