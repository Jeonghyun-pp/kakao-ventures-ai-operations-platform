### 🔴 비플랜 두 벌은 롤백 경로가 아니다 (2026-08-14 결정)

옛 표는 `bplan-automation` 의 후계를 `mail-harness/project/bplan/` 이라 적었는데 **그 경로도
이제 여기 있다**(`mail-harness-bplan-legacy`). 후계가 다시 아카이브된 것이다 — 2026-08-13 재빌드.

재빌드의 이유가 그대로 롤백을 막는 이유다. **멱등 단위가 자원과 안 맞았다**:

    옛 sync   시트 행 서수 + `Setting!A1` 커서
    옛 drop   노션 `page_id`  → 같은 사람이 5번 접수하면 **거절 메일 5통**(실측)
    새 sync   `이메일|접수시각`   · 새 drop `이메일`(1주)   ← 둘 다 **위치가 아니라 사람**

되살리면 그 결함이 그대로 발동한다. 게다가 A1 은 2026-08-02 이후 **얼어붙어 있다**:

    Setting!A1 = 5512   ·   시트 5556행   ·   그 사이 44행은 새 sync 가 이미 노션에 넣었다

옛 코드를 돌리면 5513행부터 신규로 보고 **44건을 또 만든다**(자기 장부 29개엔 그 키가 없다).
동작은 한다 — 중복을 만들면서. **비상용으로 남겨둔 것이 비상시에 사고를 낸다.**

    비플랜 롤백 = 코드를 되살리는 게 아니라 **`workers.WIRED` 에서 빼고 손으로** 한다.
                 이미 만들어진 노션 행은 접수키로 검증 가능하고, 틀렸으면 노션에서 지운다.
                 자동화 이전에 실제로 하던 방식이 그대로 폴백이다.

⚠️ `Setting!A1` 의 5512 는 이제 **아무 의미가 없다.** 사람이 그 숫자를 진행 상황으로 읽지 않도록
   주의한다(코드는 이제 A1 을 읽지도 쓰지도 않는다 — 검사 O11 이 그 상태를 잠근다).

## 🔴 왜 실행하면 안 되는가

셋이 **같은 외부 자원**을 건드린다 — Gmail 인박스 · 구글시트 A1 커서 · 노션 Bplan DB.
원본과 포크가 동시에 돌면 **중복 초안**이 생기고 **시트 행을 건너뛴다**.
불변 규칙 01: 컷오버 전에는 신·구를 절대 동시에 돌리지 않는다.

## 무엇을 했나 (2026-07-27)

1. `~/.claude/skills/` 의 심볼릭 링크를 **제거**했다 → Claude Code가 이 스킬들을 발견하지 못한다.
   문서에 "쓰지 마라"라고 적는 것은 **선언**이고, 링크를 끊는 것은 **구조**다.
   실제로 `hello-mail/SKILL.md` 에는 `"메일관리"` `"메일함 정리"` 같은 자연스러운 트리거가
   그대로 살아 있었고, `mail-harness/SKILL.md` 는 오히려 "개별 수동 작업은 원본으로"라고
   적혀 있었다 — 선언과 라우팅이 서로 모순인 상태였다.
2. 데이터(`$KV_DATA/hello-mail/`)는 **지우지 않았다.** 컷오버 롤백 절차가 원본의 존재를
   전제한다(`mail-harness/references/cutover.md`).

## 포크가 상위집합인 근거 (bplan)

함수 단위 비교 결과, 원본에만 있는 함수는 `_prompt`(대화형 입력) 하나였고 그건 무인화
방향에서 제거 대상이었다. 포크에만 있는 것은 `_load_ledger` · `_save_ledger` · `emit_result`.

포크가 고친 것: 접수 메일 미발견 시 전체 중단(원본 결함) · 멱등 레저로 중복 초안 방지 ·
대화형 input() 제거 · `--dry-run` · 하네스 결과 프로토콜.
