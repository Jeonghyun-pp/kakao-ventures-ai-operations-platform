# 그물망 판단 기준 (judge-criteria)

> **[2026-07-13] 판단은 반자동이다** — 크론이 LLM을 부르지 않는다.
> 주 1회 Claude Code 세션이 `judge-export` → **이 문서를 읽고** 판단 → `judge-apply`.
>
> ## 🔴 판정 어휘는 **채널마다 다르다** (노션 select 옵션과 **정확히** 일치해야 한다)
> | 채널 | 칸 | 허용값 |
> |---|---|---|
> | 스레드 · 링크드인 | `Tier` | `Catch \| Trend \| Wait` |
> | 앱스토어 | `판정` | `Pass \| Drop` (Tier 칸이 **없다** — 결정 #5 "판단 없는 보드") |
>
> 다른 말(A/B/C, pass/cut 등)을 쓰면 `judge-apply`가 **전량 중단**한다. 그냥 통과시키면 노션이
> 값을 조용히 버리고 PATCH는 200을 주기 때문이다 — 로그엔 "적용 완료", 판정은 전부 빈칸.
> **정본은 이 문서가 아니라 큐 파일의 행별 `allowed`다**(라이브 스키마에서 뽑는다).
>
> ⚠️ **`cut`에 해당하는 값이 Tier에 없다.** 컷한 행을 빈칸으로 두면 `judge-export`의
> `is_empty` 필터에 **매주 다시 걸린다**(무한 재순환). 4번째 옵션 신설이 미결 — 아래 [A12].
>
> ## ⚠️ 판단 룰 본문은 아직 비어 있다 (사용자가 제공 예정)
> 배선은 완성됐다. 아래 L1/L2 항목이 채워지면 그대로 프롬프트가 된다.
> few-shot 후보: 극초기 DB(`EXAMPLE_ID`)의 과거 Catch/Trend/Wait 라벨.

## 목적 (확정)
judge는 최종 결정자가 아니라 **트리아지**. 수백 raw → 사람이 5분에 훑는 **리뷰용 롱리스트**(주 10~15건).
recall 우선(놓치지 않기) + 판단 근거. **조용한 삭제 없음** — cut도 사유 로깅(감사·복원 가능).

## L1 — surface vs borderline (AI) [A4~A8]
각 후보를 다음으로 평가 → `surface`(롱리스트) / `borderline`(표시해 넘김) / (명백 부적합만 cut):
- [ ] [A4] **AI 본질**: 껍데기 AI vs 프로덕트 핵심이 AI
- [ ] [A5] **신규성**: 처음 보는 접근인가 (트렌드·카피 감점 — "정말 처음 보면 OK")
- [ ] [A6] **팀 프로필 ★핵심**: *문제를 푸는 팀* vs *바이럴/바이브코딩 슬롭*
      - 관찰된 시그널(출발점): 지표 팔로업·창업자 이력·집념(→ 문제 푸는 팀) /
        반짝 바이럴·지속성 의문·비개발자 유틸(→ 슬롭/Trend/Wait)
- [ ] [A7] **한국팀** 가중치: 해외 한국인팀 포함? 순수 외국팀 컷 vs 감점?
- [ ] [A8] surface/borderline **임계값**(confidence 상/중/하 매핑)

## L2 — Tier 제안 + 논의포인트 초안 (AI) [A9]
극초기 DB de facto 경계(관찰):
| Tier | 사례 | 시그널 |
|---|---|---|
| Catch | 찰칵AI·카라멜랩·Hash# | 문제정의 + 팀 집념/지표 + AI 본질 |
| Trend | 야장맵·내마리마찌·핑퐁 | 시장/바이럴은 있으나 팀·지속성 의문 |
| Wait | Snap View | 흥미롭지만 방향·지속성 불투명 |
- 출력: `tier_suggestion` + `pros`/`cons`(논의포인트 초안) + `one_liner` + `area`

## [A12] 컷 값 = `Cut` — **확정·적용 완료 (2026-07-19, 사용자 결정)**
`Tier` select에 4번째 옵션 **`Cut`**을 추가했다 (base · 스레드 · 링크드인 3개 DB, 라이브 확인).
- **왜 필요했나**: 컷 행을 빈칸으로 두면 `judge-export`의 `is_empty` 필터에 **매주 다시 걸린다**
  (무한 재순환). 이제 `Tier=Cut` + `AI Reason=사유`로 큐에서 빠진다.
- **사람 뷰**: `Tier != Cut` 필터. 컷도 사유가 남으므로 **조용한 삭제가 아니다**(감사·복원 가능).
- 코드 변경 **0** — `_verdict_field`가 라이브 옵션을 읽으므로 추가하는 순간 동작한다.
- 결정 #4(Tier 어휘 = 극초기 DB와 동일)와 충돌하지 않는다: **컷 행은 극초기 DB로 승격되지
  않으므로** 재매핑 문제가 생기지 않는다.
- 기존 행은 영향 없다(select 옵션 추가는 행을 건드리지 않는다). 롤백 = 노션에서 옵션 삭제.
