## 0. W2를 한 장으로

```
[전]  브레이크 = 사람의 망설임
      "돌리면 얼마 나가지..." → 크론을 꺼둠 → 그게 예산 가드였다
      그런데 net-sourcing 만 절제하고 ai-consumer 는 경고만 하고 계속 씀

[후]  브레이크 = 코드
      각 스킬 ──┐
                ├──→ 🚦 gate ──→ 💳
                ┘     "지금 얼마 남았지? 이번 건 얼마 들지?"

      그리고 끊기면 안 되는 데이터 하나를 가용성에서 분리
      맥북(간헐) ─┐
                  ├──→ 앱스토어 Δ
      GitHub(상시)┘
```

일반 이름: **control plane** · **admission control** · **execution tiering**

## 1. 자동화는 사람의 비공식 안전장치까지 같이 뺀다

`net-sourcing/SKILL.md` 에 이미 적혀 있던 문장:

> **"결정 #6(수동 실행)이 지금까지 사실상 월 예산 가드였고, 크론은 그 사람을 없앤다."**

**일반 이름 — implicit control / irony of automation**

통제가 코드에도 문서에도 없고 **운영자의 습관·불안**에만 있는 상태다.
자동화는 사람을 실행에서 빼는데, 그 사람이 하던 비공식 통제까지 같이 빠진다.
항공·산업제어에서 오래된 문제다 — 자동조종이 조종사의 이상 감지 능력까지 대체해버린 것.

**그래서 순서가 강제된다:**
```
암묵적 통제(사람) → 명시적 통제(코드) → 그다음에 무인화
                    ↑ W2                 ↑ W6
```

> **Formalize before you automate.** 명문화 안 된 규칙은 자동화 과정에서 조용히 사라진다.

## 2. 발동하지 않는 가드는 없는 가드보다 나쁘다

W2에서 가장 값나가는 발견이다.

```
Apify 플랜 실제 한도       $29
net-sourcing 이 믿던 상한  $45
                ↑
        $29~$45 = 한 번도 발동한 적 없는 가드
```

**기존 가드였다면:** `$20.07 + $10.50 = $30.57 < $45` → 통과 → Apify 가 $29 에서 끊음
→ **돈은 쓰고 결과는 반쪽.** 어느 채널이 누락됐는지도 모른다.

**없는 가드는 조심하게 만들지만, 틀린 가드는 안심하게 만든다.**

**대응 — 유효 천장 = min(우리 설정, 플랫폼 한도)**
그리고 설정이 더 높으면 경고한다. 우리 숫자가 진짜 천장이라고 가정하지 않는다.

> 일반화: **외부 시스템의 제약을 우리 설정으로 복제해 두면 언젠가 갈라진다.**
> 가능하면 **라이브로 읽고**, 못 읽으면 그 사실을 표면화한다.

## 3. 공유 자원에서 각자 관리하면 절제하는 쪽이 도태된다

```
계정 하나를 둘이 씀
  net-sourcing      월 상한 지킴
  ai-consumer       경고만 하고 계속 씀

→ ai-consumer 가 쓴 만큼 실청구액이 올라감
→ net-sourcing 이 먼저 "다 됐네" 하고 멈춤
→ ai-consumer 는 그 뒤에도 계속 씀
```

**일반 이름 — tragedy of the commons · noisy neighbor problem**

절제는 개인에게 손해고 남용은 이득이라 **절제하는 쪽이 도태된다.**
클라우드 멀티테넌시의 noisy neighbor 와 같은 구조다.

**해법은 각자를 똑똑하게 만드는 게 아니라 결정 지점을 하나로 올리는 것**
(admission control · fair share scheduling · resource quota).

**그리고 관문에는 우회로가 없어야 한다** — 옆으로 돌아갈 길이 있으면 관문이 아니다
(choke point / policy enforcement point).

## 4. 브레이크는 축이 다르면 숫자도 달라야 한다

| | 무엇을 보나 | 언제 | 걸리면 | 일반 이름 |
|---|---|---|---|---|
| preflight | 이번 런 **추정** | 실행 전 | 공짜로 중단 | admission control |
| run_budget | 이번 런 **누적** | 실행 중 | **회수 불가** | circuit breaker |
| monthly | 이번 달 **실청구액** | 실행 전 | 공짜로 중단 | quota / budget cap |

**🔴 셋을 같은 값으로 두면 안 된다.**
추정 $9.79 / 상한 $10 이면 정상 변동만으로 채널이 통째로 0건이 된다.

**일반 이름 — threshold separation / hysteresis.**
제어공학에서 켜짐·꺼짐 경계를 벌려 **떨림(flapping)** 을 막는 것과 같은 발상이다.

**그리고 추정과 실측을 구분한다**(estimated vs metered cost).
월 가드는 반드시 **실제 청구액** 기준이어야 한다 — 추정 오차가 누적되기 때문이다.

## 5. fail-open 인가 fail-closed 인가는 명시적으로 정한다

사용량 조회가 실패하면?

```
fail-closed   막는다      안전하지만 API 딸꾹질 한 번이 파이프라인을 죽인다
fail-open     통과시킨다   돌지만 그 실행은 가드 없이 나간다
```

**우리는 fail-open 을 골랐다.** 대신 **조용히 넘어가지 않는다** — 가드가 이번 실행에
적용되지 않았다는 사실을 출력한다. *"조용히 죽는 것보다 시끄럽게 도는 게 낫다."*

**중요한 건 어느 쪽을 고르느냐가 아니라 골랐다는 사실을 기록하는 것이다.**
안 정하면 코드가 우연히 정하고, 나중에 아무도 왜 그런지 모른다.

## 6. 재생 불가 소스는 가용성에서 분리한다

```
Replayable      Kafka(보존기간 내) · S3 · DB 로그
                → 놓쳐도 되감아 다시 처리 가능
Non-replayable  실시간 순위 · 시세 · 소셜 피드
                → 그 순간에 안 찍으면 영원히 없다
```

앱스토어 Δ는 후자다. 실제로 **07-20~27 8일이 비었고 복구 불가**다
(**irrecoverable data gap**).

**그래서 이 잡만 가용성이 다른 실행기로 뺀다**(execution tiering).

## 7. 배치 기준은 비용이 아니라 신뢰 경계다

> *"GitHub 이 공짜니까 다 옮기면 되지 않나"* 가 자연스러운 생각이지만 틀렸다.

```
앱스토어   공개 데이터 · 인증 불필요  → 들고 갈 열쇠가 없다 → 외부 가능
메일·노션  회사 자격증명 필요        → 열쇠를 딸려 보내야 한다 → 내부에 남음
```

**일반 이름 — trust boundary.** 이 선을 넘으면 **위험의 성격이 달라진다**:
우리 머신에서 새면 우리가 알고 폐기하면 끝이지만, 외부가 뚫리면 **우리가 모를 수도 있고
대응이 그쪽에 달려 있다.**

**규칙 하나를 정해두면 판단 비용이 0이 된다.** "조건부 허용"의 진짜 문제는
조건을 매번 판정해야 하고, **판정이 몇 번 흐려지면 경계가 사실상 사라진다**는 것이다.

**검증 방법** — 워크플로에 `secrets.` 참조가 **0건**인 것이 이 결정의 구조적 표현이다.
문서에 적는 건 선언이고, 파일에 없는 건 구조다.

## 8. 남의 컴퓨터는 실행이 끝나면 사라진다

**일반 이름 — ephemeral runner**

```
로컬     실행 → 디스크에 저장 → 남아 있음
CI 러너   임시 머신 생성 → 실행 → 💥 머신 삭제 → 결과도 증발
```

**그래서 결과를 어딘가 영속화해야 한다.** 후보 중 저장소가 가장 쌌다 —
무료이고, 이미 있고, **별도 자격증명이 필요 없다**(신뢰 경계 결정과 부합).

**부수 효과 — liveness heartbeat.** GitHub 무료 플랜은 60일 무활동이면 스케줄을
조용히 끈다. 매일 커밋하는 것 자체가 "살아 있다"는 신호가 되어 그걸 막는다.

## 9. Δ는 과거가 있어야 계산된다 — append-only

```
덮어쓰기   오늘 것으로 어제를 덮음 → 어제가 사라져 Δ 계산 불가
날짜별 축적 snapshot_2026-07-27.json / _28.json → 임의 두 시점 비교 가능
```

**일반 이름 — append-only store / snapshot-based CDC**
(소스가 변경 이벤트를 안 주면 주기적으로 전체를 찍어 비교해 변화를 뽑는다)

**그리고 브랜치를 나눴다.** 연간 365 커밋이 `main` 을 덮으면 `git log` 가 사실상
스냅샷 로그가 되어 코드 변경 이력을 못 찾는다 — 코드 히스토리와 데이터 히스토리를 분리한다.

## 10. 이음매는 나중에 만들수록 비싸다

**이건 내가 틀렸고 사용자가 바로잡은 것이다.**

나는 *"맥미니가 생기면 GitHub 을 버릴 텐데 지금 만드는 게 낭비 아니냐"* 로 봤다.
사용자의 반박: **"나눠놓으면 나중에 수정할 수 있잖아."**

```
[지금 나눔]  잡마다 "이건 어느 계층" 이라는 속성이 생김
             맥미니가 오면 → 계층 A의 구현체만 교체 (설정 변경)

[안 나눔]    모든 잡이 암묵적으로 "맥북에서 돈다"
             맥미니가 오면 → 그때 계층 개념을 새로 도입
             그리고 그때는 잡이 2개가 아니라 10개다
```

**일반 이름 — seam(이음매).** 나중에 갈라야 할 곳에 미리 만들어두는 분리 지점.
**추상화 도입 비용은 채택해야 할 대상 수에 비례한다** — 지금이 가장 싸다.

그리고 이건 기본구조가 이미 말한 것이기도 하다:
> *"상시 머신이 생기면 되돌릴 것은 없고 더할 것만 있다."*
> **그 문장이 참이 되려면 계층 분리가 먼저 있어야 한다.**

### YAGNI 와 충돌하지 않는 이유

```
투기적 추상화  "나중에 필요할 것 같아서"        → YAGNI 위반
관측된 요구    "이미 8일 끊겼고 영구 손실이다"   → 대응
```

## 1번을 따로 적는 이유

무인화 방식이 셋인데 나는 하나만 봤다.
```
① API 키      종량 과금 · 어디서든 실행 가능
② claude -p   구독 유지 · 우리 머신에서만       ← 이게 있었다
③ tmux 주입   구독 유지 · 상주 세션 필요        ← 덱이 쓴 방식
```
**그리고 문제가 사라진 게 아니라 성질이 바뀐다:**
```
API 키   많이 쓰면 → 돈이 나간다
구독     많이 쓰면 → 쿼터가 소진된다 → 사람이 못 쓴다
```
돈이 안 드니까 무제한이 아니다. **덱 8단계 usage-gate 가 처음부터 이 이야기였다** —
"멈춘 세션은 자동 재개"는 API 이야기가 아니다.

## 4번 — 대리 지표(proxy metric)의 함정

```
확인하려던 것   러너에서 차트 데이터를 파싱할 수 있는가
실제 잰 것      페이지 본문에 특정 문자열이 있는가   ← 대리 지표
결과            대리 지표는 실패, 본체는 정상
```
**대리 지표가 틀리면 멀쩡한 걸 고장으로, 고장난 걸 멀쩡한 것으로 읽는다.**
결국 실제 워크플로를 돌려 84개 차트가 나오는 걸 보고서야 확정했다.

## 6번 — [2026-08-02 추가] 검증은 환경에 종속된다 (temporal coupling · env-dependent test)

계층 A 는 W2 에서 C1 으로 검증했는데도 **예약 실행이 나흘 내리 실패**했다. 검증했는데 왜 깨졌나.

```
C1 검증       수동 실행 · 07-28 10:23 UTC  → UTC·KST 같은 날짜 → 통과
예약 실행      매일 · 20:10 UTC(=05:10 KST) → UTC·KST 다른 날짜 → 실패
```

**근본 원인 — 타임존 날짜 경계.**
`board.py::_save_snapshot` 은 `date.today()`(러너 로컬 = UTC)로 파일명을 짓고,
검증은 `date -u -d '+9 hours'`(KST)로 찾았다. 05:10 KST 실행에서 board 는 어제(UTC) 날짜로
저장하는데 검증은 오늘(KST)을 찾아 **0개로 오판, 커밋 전 exit 1**. 84개는 매번 정상 수집됐고
**날짜 불일치로 스스로 폐기**됐다(네트워크·지역 무관, URL 은 `/kr/` 하드코딩).

**왜 못 잡았나 — 세 겹.**
```
① 검증이 한 조건에서만 이뤄졌다   15:00 UTC 이전 수동 실행. 경계 넘는 시각을 안 밟았다
② 맥(KST)에선 재현 안 됨          board·검증이 같은 TZ 라 로컬에선 영원히 안 터진다
③ 실패가 사람에게 안 닿았다        GitHub 메일은 왔으나 안 봄 (알림 비대칭 = 대가 ③)
```

**교훈 셋.**
- **한 조건의 통과 ≠ 모든 조건의 통과.** 특히 시각·타임존·로케일처럼 *언제 도느냐로 값이 바뀌는*
  것에 의존하면, 검증은 **경계를 넘는 조건에서** 해야 한다. `date.today()` 는 순수 함수가 아니다.
- **개발 환경과 실행 환경이 다르면 버그는 실행 환경에서만 산다.** 맥(KST)=개발, 러너(UTC)=실행.
  → 수정도 "러너를 맥과 같은 TZ 로" 가 정답이었다(`TZ: Asia/Seoul`).
- **자기폐기는 유실보다 낫지만 유실처럼 보인다.** 게이트(불변 규칙 06)가 쓰레기를 막은 건 옳았다.
  다만 "성공(exit 0)했는데 산출 0" 을 **사람에게 시끄럽게 알리는 경로**가 없어 5일을 몰랐다.
  → W3(상태·이벤트 규약)·W7(관측)이 갚을 부채가 여기서 구체화된다.

**대가.** 08-01(KST)은 클라우드 실패 + 맥 꺼짐으로 양쪽 공백 = **복구 불가 1일**.
그리고 이중화(launchd)를 **아직 안 지운 게 07-30·31 을 살렸다** — "3일 관찰 후 제거" 를
그대로 실행했으면 그 이틀도 날아갔다. **이중화는 대체재가 3일 연속 검증되기 전엔 걷지 않는다.**

# 가져갈 것 — 10줄

```
1. 자동화 전에 사람이 하던 비공식 통제를 코드로 옮긴다     (irony of automation)
2. 발동하지 않는 가드는 없는 가드보다 나쁘다               (틀린 가드는 안심시킨다)
3. 외부 제약은 복제하지 말고 라이브로 읽는다               (min(우리 설정, 실제 한도))
4. 공유 자원은 각자 말고 관문 하나로                      (tragedy of the commons)
5. 축이 다른 브레이크는 숫자도 달라야 한다                 (threshold separation)
6. fail-open/closed 를 명시적으로 고르고 기록한다
7. 재생 불가 데이터는 가용성에서 분리한다                  (execution tiering)
8. 배치는 비용이 아니라 신뢰 경계로 정한다                 (trust boundary)
9. 검증은 경계를 넘는 조건에서 한다                        (env-dependent test) ← 08-02
10. 이중화는 대체재가 연속 검증되기 전엔 걷지 않는다        (don't remove the fallback yet) ← 08-02
```
