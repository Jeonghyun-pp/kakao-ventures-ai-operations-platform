## 1. 🏗 구조가 없앰 — 재설계로 **존재할 수 없게** 된 것

이것들은 개별 수정을 하지 않았다. 판정·발송·상태가 한 곳으로 모이면서 결함의 전제가 사라졌다.

| ID | 무엇이었나 | 왜 이제 불가능한가 |
|---|---|---|
| A-M6 | orrery `❌거부` 가 어떤 입력에도 0인 죽은 카운터 | 승인 통계를 `pending()` 이 아니라 **전량 기준**으로 계산(`health._approvals`). 오늘 승인·거부·실행이 표면에 남는다 |
| A-M7 | 승인된 judgment 가 pending 에 무한 누적 | `_is_closed` 가 kind 의미론을 따른다 — 실행이 없는 kind 는 **결정되면 끝** |
| B-H3 | 보상 재푸시가 `gate_block` 전용 | `dispatch` 가 오늘 관측된 **모든** 사실을 훑는다. kind 특례라는 개념이 없어졌다 |
| B-M2 | `scan()` 격리가 3번째 클래스에 미적용 | 원천이 전부 `_try` 로 감싸인 **같은 목록**이 됐다. 예외가 하나 |
| B-M5 | 레거시 `pushed: true` 오판 → 중복 재푸시 | 이벤트의 `pushed` 필드를 **읽지 않는다**. 발송 여부의 정본은 dedup 마커 하나 |
| B-M6 | "전부 실패한 날" 슬랙 트래픽 0 | 다이제스트 게이트가 `state.reds()` 를 본다 + `dispatch` 는 스케줄러와 무관하게 10분마다 돈다 |
| B-L2 | `first_attempt` 백필이 사람 손 | 잡 디렉토리에서 최초 시도일을 복원하고 **더 이른 쪽**을 택한다(자기치유) |
| C-H5 | `setdefault` 가 시계 리셋 | 위와 같은 메커니즘 — 리셋된 워터마크도 잡 흔적이 되돌린다 |
| C-M1 | 다이제스트 게이트가 해결분까지 셈 | 표시와 게이트가 `reds()` 라는 **하나의 판단**을 공유한다 |
| C-M2 | launchd-direct 가 freshness 선언 무시 + 알림 커버 0 | `health` 는 러너와 무관하게 같은 규칙으로 판정한다 |
| C-H6 | 부재 감지기가 부재의 원인 안에 삶 | 판정이 `compute()` 로 나오면서 **10분 틱이 스케줄러 밖에서** 본다 |
| C-L4 | 파손된 completed 가 해결 판정에서 누락 | 파손은 "순서 미상 → 해결 판정 보류"로 명시 분기(보수적 방향) |
| B-M3 (=C-M7) | 경과일 KST vs 마커 UTC 혼용 | 판정이 `health` 로 모이면서 **전부 UTC**. `alerts` 에 날짜 계산이 남아 있지 않다 |

## 4. 🆕 리뷰가 못 찾았고 이번에 새로 찾은 것 — 4건

**N1·N2 는 8/7 수정이 만든 것**이고 동시성 랩이 잡았다(검증 사각 ①을 닫자마자 나왔다).
**N3·N4 는 이번 재설계가 만든 것**이고, 적대 리뷰 에이전트가 API 오류로 죽은 뒤
그들이 볼 예정이던 지점을 직접 프로브해서 찾았다.

| # | 결함 | 누가 만들었나 | 심각도 |
|---|---|---|---|
| N1 | **first-decision-wins 가 경합에서 깨져 있었다**(8/8 전부 불일치) — Phase 0 이 유령 락을 없애며 last-write-wins 로 되돌아갔고 단일 프로세스 테스트가 통과시켰다 | 8/7 수정 | 🔴 |
| N2 | **거부된 건이 `status=executed` 로 확정** — 재확인이 `create_draft` **전**에만 있어 초 단위 Gmail 호출 중 들어온 거부를 못 막았다 | 8/7 수정 | 🔴 |
| N3 | **결정 마커가 key 에만 묶여 옛 결정이 되살아났다** — 레코드를 지웠다 같은 key 로 재생성하면 새 건이 아무도 결정하지 않았는데 자동 거부/자동 승인된다. `meeting-mail` 의 dedup_key 는 page_id 라 실제로 도달하는 경로다 | **이번 재설계** | 🔴 |
| N4 | **스케줄러 침묵 임계 8시간이 오탐 제조기** — "주기 4시간이니 2주기"로 추측했는데 실 로그의 발화 간격은 최대 **18.4시간**(17구간 중 4개가 8시간 초과). 맥이 자면 launchd 가 안 돌고 그건 이 환경의 정상이다 | **이번 재설계** | 🟠 |

**패턴이 네 번 반복됐다**: 킬 스위치 → decide 락 → 결정 마커 → 침묵 임계.
전부 "고치면서 새로 심은 것"이고, 전부 **그 수정을 대상으로 한 검증이 있어야만** 보였다.
배치 A(검증 능력)를 리팩터 앞에 둔 판단이 옳았고, **그것으로도 충분하지 않았다** —
N3·N4 는 배치 A 의 랩이 아니라 "이 수정이 무엇을 깨뜨릴 수 있나"를 따로 물어서 나왔다.

N4 의 교훈은 따로 적어둘 값어치가 있다: **임계는 추측하지 말고 실측한다.**
"주기 4시간이니 8시간"은 그럴듯했고 틀렸다. 로그를 한 번 세는 데 1분 걸렸다.
