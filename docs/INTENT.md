# 의도 — 무엇을 만들기로 했나

> **인턴 업무를 어떤 실패도 조용히 지나가지 못하는 최소 구조로 자동화한다.**

이 문서는 장식이 아니라 **검사 기준**이다. 코드를 한 덩이 지을 때마다 여기 와서
하나씩 대조한다. 못 지킨 게 있으면 지켰다고 적지 말고 **못 지켰다고 적는다.**

---

## A. 기계가 세는 것

돌려서 통과/실패가 나와야 한다. `check_intent.py` 가 이걸 센다.

| # | 의도 | 어떻게 세나 |
|---|---|---|
| A1 | **통로는 소스마다 하나** | 통로 파일 밖에서 `requests`·외부 SDK import 0건 (AST) |
| A2 | **0과 미상을 가른다** | 통로 반환이 전부 `Fetched`. `.value` 직접 접근 0건 |
| A3 | **rc 로 성공을 판정하지 않는다** | `returncode == 0` 을 성공 근거로 쓰는 곳 0건 |
| A4 | **쓴 것은 되읽는다** | 노션 쓰기 함수에 되읽기 없는 경로 0건 |
| A5 | **옵션을 코드에 박지 않는다** | select 값 문자열 리터럴 0건 (라이브 스키마에서 읽는다) |
| A6 | **제약 숫자를 코드에 박지 않는다** | `2000`·`200`·`100`·`0.34` 같은 값이 `constraints` 밖에 0건 |
| A7 | **돈은 꼬리표 없이 못 쓴다** | 유료 호출에 `skill` 인자 필수 (없으면 TypeError) |
| A8 | **발송 경로가 없다** | 코드 전체에 Gmail `send` 호출 0건 (AST) |
| A9 | **선언과 설치가 일치한다** | `SKILL.md` 스케줄 선언 ↔ launchd 실제 설치 대조 |
| A10 | **검사가 실제로 문다** | 방어 코드를 되돌리면 검사가 실패한다 (변이 테스트) |
| A11 | **테스트가 망을 안 부른다** | 테스트 중 소켓 연결 0건 |
| A12 | **테스트가 프로덕션을 안 건드린다** | 테스트 전후 `~/kv-data` 스냅샷 대조 |

## B. 사람이 보는 것

기계로 못 세지만 매 단계 눈으로 확인한다.

| # | 의도 | 확인 방법 |
|---|---|---|
| B1 | **못 한 일을 숨기지 않는다** | 망을 끊고 돌려본다. "0건"이 아니라 "못 붙었다"가 나오는가 |
| B2 | **되돌릴 수 있는 건 안 묻는다** | 사람에게 묻는 지점을 센다. 늘었으면 왜 늘었나 |
| B3 | **사람이 이미 있는 곳으로 간다** | 새로 봐야 할 화면이 생겼나. 생겼으면 안 된다 |
| B4 | **스킬끼리 안 부른다** | 다른 스킬을 import 하거나 그 파일을 읽는 곳이 있나 |
| B5 | **하나 지워도 안 깨진다** | 스킬 폴더를 지워보고 다른 게 도는지 확인 |
| B6 | **claude 가 틀려도 "덜 함"이다** | 절차를 일부러 건너뛰고 돌려본다. 데이터가 망가지나 |
| B7 | **보고가 장부에서 나온다** | 착지를 막고 돌려본다. 보고가 0건이라고 하는가 |
| B8 | **방어 코드가 근거를 가리킨다** | 새 방어 코드마다 [0] 제약 중 무엇인지 적혀 있나 |
| B9 | **신호 없이 층을 안 만든다** | 이번에 만든 것 중 "아직 안 겪은 문제"를 막는 게 있나 |

## D. 이 문서를 쓰는 법

새 기능을 붙이려 할 때 두 번 묻는다.

1. **사람 인턴이라면 이걸 할까?** 안 할 것 같으면 안 만든다.
2. **이게 조용히 실패할 수 있나?** 그렇다면 **시끄럽게 만드는 장치를 같이** 만든다.

두 번째 답이 없으면 그 기능은 아직 완성이 아니다.
