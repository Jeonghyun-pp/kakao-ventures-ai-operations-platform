# ADR 0003 — AI는 claude -p 구독으로 단일화한다 (API 키 없음)

> 상태: **초안 — 검토 필요** (판단 칸은 세션 논의를 정리한 것. 본인 문장으로 다시 쓸 것)
> 날짜: 2026-08-03 · 결정자: 박정현

---

## 맥락 — 결정 시점의 사실

### 지금 AI를 부르는 방식이 두 갈래로 갈려 있다

| | 메커니즘 | 어디서 | 비용 |
|---|---|---|---|
| 사실 분류 | **Anthropic API** (`anthropic.Anthropic()`) | `net-sourcing/core/llm.py`(스레드·앱스토어·링크드인) · `mail-harness/triage/core/llm.py` | MTok당 과금·상한 없음 |
| 판단 | **claude -p 구독 세션** | `net-sourcing/core/judge_cli.py`(주 1회 수동 세션) | 구독 내 |

두 메커니즘이 공존하는 어정쩡한 상태다. API 경로는 `ANTHROPIC_API_KEY` 를 요구하고, 그건 **무인 크론에 붙으면 상한 없는 지출**이다.

### 이건 이미 두 번 예고됐다

- **W2 레슨 #1** — *"무인화 = API 과금 시작이라 단정했는데, `claude -p` 로 구독 유지가 가능했다. 덱이 이미 쓴 방식인데 못 연결했다."* 무인화 방식은 셋(①API 종량 ②claude -p 구독·우리 머신 ③tmux 상주)인데 하나만 봤다.
- **ADR 0002 대가 ②** — *"게이트가 실제 소비의 일부만 덮는다. Claude 구독 소비는 계측 경로가 없다. W6에서 다시 봐야 한다."*
- **ADR 0002 판정 시점** — *"Claude 구독 쿼터가 새 병목이 되는지 W6에서 드러난다."*

이 ADR은 그 미뤄둔 결정을 지금 확정하는 것이다.

---

## 결정

**① 모든 AI 호출을 `claude -p` 구독 세션으로 단일화한다. API 키 의존을 제거한다.**
`core/llm.py`(API 분류기)는 은퇴하고, 사실 분류도 `judge_cli.py` 가 증명한 패턴(export→세션→apply)으로 흡수한다.

**② 결정론적 통제는 코드, 판단·생성만 claude.**
"언제 뭘 돌리나"(due 판정·catch-up·체크포인트·락·멱등)는 전부 코드가 한다. claude는 "좋은 팀인가·메일 초안" 같은 **머리가 필요한 칸에만** 불려온다.

**③ claude 구독 = 공유 자원 → 단일 관문.**
구독 쿼터는 모든 task가 나눠 쓰는 자원이다. `tasks.yaml` 에 `claude` 를 자원으로 등록해 스케줄러가 세션 호출을 직렬화하고, 게이트(W2 gate.py)를 **"$ API 과금" 대신 "claude -p 호출 빈도·쿼터"** 감시로 재타깃한다(W6).

**④ claude 출력은 강제(hard)가 아니라 권고(soft) → 되읽기 검증 필수.**
API의 `json_schema` 는 스키마를 **어길 수 없게** 강제했다. `claude -p` 는 스키마를 줘도 "잘 따름"이지 강제가 아니다. 그래서 출력을 **한 줄씩 되읽어 검증**하고, 어긋나면 멈춘다(fail-closed). 이는 W5 `validating` 스테이지를 "옵션"에서 "생명줄"로 승격시킨다.

### 왜 하나로 합치나

두 메커니즘은 신뢰 모델·비용 축·실패 양상이 다르다. 무인화하려면 "돈이 나가는 경로(API)"를 파이프라인 어디에도 두면 안 된다 — 크론이 부르는 순간 상한 없는 지출이 시작된다. 구독으로 통일하면 **비용 축이 "돈"에서 "쿼터"로 바뀌고**, 쿼터는 사람이 회복 가능한(=치명적이지 않은) 실패다.

### 왜 코드가 통제하고 claude는 판단만 하나

"오늘 실행할 날인가?"는 날짜 빼기다 — 정답이 있고, 틀리면 안 되고(틀리면 메일 2회 발송 같은 비가역 사고), 공짜고, 테스트된다. 이런 결정론적 판단에 "가끔 헷갈리는 확률적 모델"을 두면, 시스템에서 **가장 신뢰가 필요한 부분에 비결정성**을 심는 꼴이다. claude는 정답이 없는 판단(사람도 갈리는 것)에만 쓴다.

### 왜 구독이 공유 자원인가

W2 레슨 #3(공유지의 비극)의 재현이다. 여러 task가 각자 claude -p를 부르면 쿼터를 두고 경쟁하고, 절제하는 task가 도태된다. 해법은 각자를 똑똑하게 만드는 게 아니라 **결정 지점을 하나로 올리는 것**(admission control). `resources: [claude]` 로 등록하면 자원 락이 세션을 직렬화한다.

## 결과

| 항목 | 전 | 후 |
|---|---|---|
| AI 호출 경로 | API 분류기 + claude 세션 (2갈래) | **claude -p 세션 (1갈래)** |
| `ANTHROPIC_API_KEY` 의존 | 있음(`core/llm.py`) | **제거** |
| 코드가 claude를 부르는 통로 | 산발(anthropic 클라이언트 여러 곳) | **`kv_core/session.py` 단일 통로** |
| 비용 축 | 돈(상한 없음) | **쿼터**(사람 회복 가능) |
| 게이트 감시 대상 | $ API 과금 | **claude -p 호출·쿼터** (W6) |
| claude 출력 신뢰 | (API는 스키마 강제) | soft → **되읽기 검증 필수**(W5 validating) |
| judge 무인성 | 주 1회 수동 세션 | **무인 `claude -p` 스테이지로 승격** (W5~) |

**검증(W5):**
- ✅ **무인 인증 스모크 통과 [2026-08-03]** — LaunchAgent(TTY 없음, 최소 환경)에서 `claude -p` 가 화면 잠금 ~3분 구간 내내 60초마다 `OK`, 에러 0. **claude 구독 인증이 잠금-깨어있음(locked-awake) 상태에서 유지됨**을 확인. → 대가 ①(최대 리스크)이 이 조건에서 해소.
  - *단서: (a) 잠자기(sleep)는 미검증 — StartInterval 잡은 sleep 중 지연·coalesce되므로 W6 wake-bootstrap 소관. (b) 화면잠금 자동감지는 pyobjc 부재로 실패, 사용자 잠금 구간+타임스탬프로 판정.*
- 남은 검증: `session.py` 좁은 도구 허용목록(`_assert_no_send` 상속) · validating fail-closed · 한 수직선 draft까지 발송 0.

## 대가 — 무엇을 잃었나

**① 무인 실행이 세션 인증에 의존한다.** 맥북이 잠긴 채 launchd가 `claude -p` 를 깨울 때 구독 인증이 살아있어야 한다. API 키(환경변수 한 줄)보다 취약할 수 있다. → **W5 선행 스모크 테스트로 먼저 확인.** 여기가 최대 리스크.

**② 구조화 출력의 하드 보장을 잃는다.** API의 `json_schema` 강제가 사라져, 되읽기 검증이라는 상시 비용이 생긴다. 다만 이 검증은 `judge_cli.apply` 가 이미 하던 것(전량검증 후 반영)이라 새 부채는 아니다.

**③ 쿼터가 새 병목이 된다.** 돈이 안 드는 대신, 많이 쓰면 쿼터가 소진돼 **사람이 claude를 못 쓴다**(W2 레슨 #1). 배치(세션당 다건)로 호출 횟수를 줄이고 게이트로 감시해야 한다.

**④ "우리 머신에서만" 제약.** claude -p 구독은 우리 머신에 묶인다(외부 CI 러너 불가). 앱스토어처럼 신뢰 경계 밖으로 뺀 잡과 달리, claude 판단은 **내부에만 산다**(ADR 0002 신뢰 경계와 정합 — 오히려 강화).

## 이 결정이 틀렸다면 어떻게 알 수 있나

### 🔴 결정적 신호
- **무인 `claude -p` 가 인증 만료로 조용히 실패한다.** launchd 로그에 로그인 요구가 뜨고 판정 파일이 안 생긴다. → API 키로 부분 회귀하거나 tmux 상주(③)를 검토해야 한다.
- **쿼터 소진으로 사람이 claude를 못 쓰는 날이 생긴다.** 무인 소비가 사람 몫을 잠식한 것 — 게이트 임계값이 틀렸다.

### ⚠️ 경고 신호
| 신호 | 뜻 |
|---|---|
| validating 실패율이 높다 | claude 출력이 soft라 자주 삐끗 — 프롬프트·스키마·배치크기 재조정 필요 |
| `--force` 로 게이트 우회가 잦다 | 쿼터 임계값이 실제 패턴과 안 맞음 (ADR 0002와 같은 신호) |
| 세션 직렬화로 파이프라인이 느려진다 | `resources:[claude]` 직렬화가 과하다 — 병렬 허용 재검토 |

### 판정 시점
**W5(무인 스모크 + 첫 수직선)** 가 첫 시험이다. 인증이 무인에서 버티는지, 되읽기 검증이 soft 출력을 실제로 잡는지가 그때 드러난다. **W6(게이트 재타깃)** 에서 쿼터가 병목인지 확정된다.
