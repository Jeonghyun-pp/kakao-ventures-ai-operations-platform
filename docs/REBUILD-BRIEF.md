# 재빌드 브리프 — 무엇을 만드는가 (2026-08-16)

**이 문서 하나만 읽고 시작할 수 있게 쓴다.** 다른 세션이 이걸 받아 새 리포에서 설계를 시작한다.

---

## 0. 결정 (2026-08-16)

**새 리포에서 재빌드한다.** 현행 코드는 버리고, **측정으로 확보한 자산은 가져간다.**

```
가져간다   계약 문서 12본(588K) · 검증 스위트 28본(7,986줄) · 교훈 18본
           ~/kv-data 861MB(상태 전량) · ~/kv-config(시크릿)
버린다     kv_core 6,009줄 · skills 25,180줄 · 커밋 이력
```

크론 3개(`com.kv.scheduler` · `com.kv.approvals` · `com.kv.net-sourcing.appstore`)는
**정지했다.** plist 파일은 남겨 뒀다(되살릴 때 참고). 재빌드 중 옛 코드가 노션에 쓰거나
메일을 읽지 않는다.

### 왜 재빌드인가 — 설계가 틀려서가 아니다

전수 감사(코드 313본 · 노션 10,102행 · 상태 8,606파일 · 액터 원본 8,038본) 결과
**코드가 선언한 규약이 실데이터에서 반증된 곳은 0건**이었다. 설계는 대체로 맞았다.

문제는 다른 데 있었다:

> **설계가 지켜지는지 세는 장치가 없었다.**

그래서 "선언은 있는데 발동하지 않는 가드"가 반복해서 생겼고, 고칠 때마다 새 층이 덧대어져
30,122줄이 됐다. 재빌드의 목표는 **더 나은 설계**가 아니라 **선언과 실행이 갈라지지 않는
구조**다.

## 1. 무엇을 만드는가

**카카오벤처스 인턴 업무를 완전 자동화하는 하나의 에이전트 시스템.**

지금 자동화 대상인 업무(현행 기준):

```
그물망 소싱   앱스토어·스레드·링크드인에서 극초기 창업자 발굴 → 판정 → 노션 착지
비플랜 처리   접수된 사업계획서 1차 스크리닝 → 점수 → 담당자 라우팅
메일 트리아지  hello@ 인바운드 분류 → 라우팅/아카이브/에스컬레이션
미팅 요청     Catch 판정 창업자에게 메일 초안 → 사람 승인 → 발송
관측          매일 브리핑(오러리) · 알림 · 승인 큐
```

이 프로젝트는 **목적이 둘**이다. 자동화 제품을 만드는 것이 절반, **구조 설계와 데이터
엔지니어링을 배우는 것**이 나머지 절반이다. 그래서 "돌아가면 됐다"가 아니라 **왜 그렇게
했는지가 남아야** 한다.

🔴 **[6]이 무엇인지 정하고 시작하라.** 이전 세션까지는 [0]~[5] 6개 층으로 합의했는데,
사용자가 "0~6층"이라 했다. 새 층을 세운 것인지, 세는 방식이 다른 것인지 **확인 없이
추측하지 마라.**

## 4. 반복해서 당한 실패 — 이걸 막는 구조를 만드는 게 목표다

전부 실제로 일어났고, 대부분 **여러 번** 일어났다.

**① 선언은 있는데 발동하지 않는 가드**
- 문서 4곳이 `~/kv-data` 를 *"rsync 단위"* 라 선언했는데 백업이 **하나도 없었다**(981MB 유일본)
- `refresh: monthly` 가 선언돼 있지만 커서 소진이 1.8년 뒤라 그 선언은 사문
- `judge-appstore` 계약은 살아 있는데 호출 선언이 없다
- 인증 만료 알림이 `ok=(rc==0)` 때문에 **자기 목적 시나리오에서 영원히 미발동**

**② 0 이 두 뜻인데 갈라 보지 않는다**
- 앱스토어 수집이 DNS 실패로 전멸했는데 `✅ 0건` + 종료코드 0 (전날 10,112건)
- 카지노 유료 차트가 원래 비어 있는 것을 "결손"으로 읽어 **매일 경보**
- 계측이 0 인 것과 전멸이 같은 값이었다

**③ 두 진실원**
- 월 천장이 `resources.yaml $29` vs `config.yaml $45` — 조회 한 번 실패하면 유효 천장이 조용히 $45
- `task-registry-mirror.md` 가 `tasks.yaml` 의 사본인데 15개 중 5개가 빠져 있었다
- 프롬프트에 출력 형식을 손으로 적어 계약과 갈라짐

**④ 로컬은 초록인데 CI 에서만 죽는다 (또는 그 반대)**
- 합성 테스트가 심볼릭 링크로 `KV_DATA` 를 우회해 **넉 달간 프로덕션 데이터에 썼다.**
  그 링크는 gitignore 라 CI 엔 없어서 **원리적으로 CI 가 못 보는 결함**이었다
- `.venv/bin/python` 하드코딩 — 하루에 **네 번** 밟았다

**⑤ 내용이 구조를 깬다**
- claude 가 `reason` 에 이스케이프 없는 `"` 를 넣어 JSON 배열이 깨지고 **배치 16건 전량 유실**
  (2회 = 32건, 약 2.3%) → 전송 형식을 탭 구분으로 바꿔 부류를 없앴다

**⑥ 지우기 전에 안 본다**
- 삭제 예정이던 사문 데이터 4건 중 **3건이 죽은 게 아니었다**

**⑦ 문서가 실측을 못 따라간다**
- 계약이 "죽은 수집기"라 적은 것이 사실은 위 ④의 테스트 누출이었다
- 존재하지 않는 설정 키(`config.retention`)를 계약 문서에 적었다 — **내가 지어낸 이름**

### 그래서 새 리포가 지켜야 할 규율

```
· 인스턴스가 아니라 **부류**를 막는다. 같은 함정을 두 번 밟으면 검사를 만든다
· 잡히지 않는 변이는 고쳐진 것이 아니다 — 고침을 되돌려 검사가 무는지 확인한다
· "대체로/대부분" 금지. **읽은 수 / 전체 수**로 말한다
· 0 이 두 뜻이면 둘을 갈라 본다
· 진실원은 하나. 사본을 만들 바엔 생성물로 만든다
· 조용한 스킵 금지 — 못 한 것은 **시끄럽게** 못 했다고 한다
```
