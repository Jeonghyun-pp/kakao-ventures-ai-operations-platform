### E — 이번에 나온 가장 중요한 결함

```
_synthetic_apify_gate → pipeline.collect → RAW = PROJ/"data"/"raw"
                                           data ─심볼릭 링크→ ~/kv-data/net-sourcing
```
net-sourcing 은 `kv_core.paths` 를 안 거치므로 **`KV_DATA` 스크래치가 무효**였다.
그 링크는 `.gitignore` 라 CI 러너엔 없어서 **원리적으로 CI 가 못 보는 결함**이었다 —
초록 CI 뒤에 넉 달 숨어 있었다. 피해 12본 중 `threads_<D>` 4본은 **실채널 이름**이라
"raw 최신본을 읽는" 하류가 테스트 산출물을 진짜 수집 결과로 소비할 수 있었다.

고침을 두 겹으로 했다 — 인스턴스(그 테스트의 `RAW` 를 스크래치로)와 **부류**
(`kv-core/tests/run_suite.py`: 테스트 전후 `~/kv-data` 스냅샷 대조, 건드린 테스트 이름을
대며 실패). 변이 시험으로 가드가 세 파일을 정확히 짚는 것까지 확인했다.

**이 결함이 남긴 규율**: 삭제 예정이던 사문 데이터 4건 중 **3건이 죽은 게 아니었다.**
`listly` 는 "죽은 수집기"가 아니라 위 누출, `.pending` 은 유실이 아니라 완료된 원자쓰기
잔재, `hello-mail/` 은 이관이 끝나 있었다. **지우기 전에 반드시 실측한다.**

### 결정 2건

**① `~/kv-data` 백업 배선** — 981MB 유일본에 백업이 하나도 없었다. 문서 4곳이
*"rsync 단위"* 라 선언했지만 crontab·launchd 어디에도 없었다(**선언만 있고 발동하지 않는
가드**). rsync `--link-dest` 하드링크 스냅샷 7일 보관 + 스케줄러 task 로 배선.
복구까지 실증했다(원본을 통째로 지우고 어제 스냅샷에서 150/150 파일 복원).

**② 판정 계약 JSON → 탭 구분** — claude 가 `reason` 안에 이스케이프 없는 `"` 를 넣어
배열 전체가 깨지고 배치 16건이 통째로 유실됐다(2회 = 32건, 약 2.3%).

```
JSON 에서 `"` 는 내용이면서 동시에 구분자다
    → 내용 한 글자가 구조를 파괴한다 → 파괴 범위가 배치 전체다
```
파서를 관대하게 만드는 대신 **형식을 바꿨다** — 탭 구분 + 자유 텍스트 맨 뒤 + `maxsplit`.
따옴표·괄호·탭이 전부 그냥 글자가 되고, 한 줄이 깨져도 **그 줄만** 죽는다.
실 claude 1회 호출로 준수를 확인했다(탭 4열 정확 · 깨진 줄 0 · 계약 2/2 통과).
