## 2. 노션 자동화 — 오늘 실측

체크박스 하나가 **두 DB 에 동시에** 행을 만든다. 08-18 04:20 에 체크 5개를 켰더니
같은 분에 Pick 5행 + 극초기 5행이 생겼다.

```
링크드인 소싱 DB · `DB로 업데이트` ✅
   ├─→ ⭐ Pick      서비스명←서비스명 · 링크←LinkedIn URL · 설명←One Liner · 채널=LinkedIn
   └─→ 극초기 DB     법인(서비스)←서비스명 · 링크←LinkedIn URL · 한 줄 설명←One Liner · 발굴=링크드인
                    담은 날짜 · 슬랙 발송? 는 안 채운다
```

`설명`이 One Liner 복사인 것이 근거다 — `Example Person B` → *"집중력 관리를 돕는 AI 에이전트 앱"*,
`Example Person C` → *"(주)예시법인"*, `Example Person A` → *"Various Companies"*. 소스 DB 의 One Liner 값 그대로다.

체크 현황: **링크드인 23 · 앱스토어 14 · 스레드 2** (링크드인 23 = 기존 18 + 오늘 5)

## 3. 문제 13건

### 구조

**① 소싱 DB 가 4벌 — 세대가 안 지워졌다**
```
07-09  테스트페이지 (37칸 · 180행)     1세대 · 죽음
07-14  base 자동화  (56칸 · 1,470행)   2세대 · 죽음  ※ DB 최종수정은 08-15 — 누가 최근에 건드렸다
07말~  채널 3DB     (21·41·41칸)       3세대 · 현행
```
재구조화할 때마다 새 DB 를 만들고 **옛 것을 한 번도 안 지웠다.** 죽은 표시도 없다.

**② `READ_ONLY` 가 죽은 선언** — `kv_transport/notion.py:47`. 3개 등록했는데 참조 0건.

**③ 스레드 DB 는 살아 있는데 스킬이 없다** — 635행 · 체크박스 7개. `~/kv/skills/` 에 스레드가 없다.

**④ base 의 부모가 DB 의 행이다** — `EXAMPLE_ID` 는 제목 없는 페이지이고 그 부모가 또 database 다.
상위는 통합 미공유라 안 보인다.

**⑤ 스키마가 제각각** — 21 / 41 / 41 / 56 / 37 / 16 / 5칸. 한 사람이
채널 DB(41칸) → Pick(5칸) → 극초기(16칸) 로 가며 **칸이 두 번 줄어드는데 무엇이 버려지는지
어디에도 안 적혀 있다.**

### 데이터

**⑥ 🔴 극초기 `법인(서비스)` 에 사람 이름이 들어간다**
자동화가 `서비스명`(=사람 이름)을 그대로 복사한다. 오늘 5건(`Example Person B`·`Example Person A`·`Example Person D`·
`Example Person C`·`Example Person E`), 08-12 배치 10건이 그렇다.
**극초기는 dedup 대조원이라 title 이 회사명이 아니면 다음 수집의 중복 판정이 조용히 어긋난다.**

**⑦ 극초기에 `SampleProduct` / `Example Person B` 두 행** — 같은 사람. 링크가 하나는 `product.example.com`, 하나는
`linkedin.com/in/example-person` 이라 **링크 키로도 안 잡힌다.** (2026-08-18 내가 만든 중복)

**⑧ 극초기 링크 중복 4쌍**
```
SampleProductA × 2         같은 이름 · 같은 링크
샘플제품가 × 2          같은 이름 · 같은 링크
SampleProductB / 샘플제품나         한글·영문 두 행
SampleProductC / SampleProductD   🔴 이름이 다른데 링크가 같다 — 오기 의심
```

**⑨ 링크가 공백 한 칸(`' '`)인 행 5개** — 샘플제품다·샘플제품라·샘플제품마·샘플제품바·뜰.
빈칸(미상)과 값 있음이 구별 안 된다.

**⑩ Pick 에 `담은 날짜` 없는 행 12개** — 자동화 생성분. "언제 올렸나"를 못 센다.
(Pick 27행 = 사람이 쓴 10 + 자동화 12 + 오늘 손으로 쓴 5)

**⑪ Pick `설명`이 두 종류** — 사람이 쓴 ▸서식 300~900자 vs 자동화의 One Liner 복사 **2~95자**
(`'--'` · `'CEO'` 같은 것도 있다).

**⑫ 앱스토어 체크 14건 중 10건 미승격** — 전부 07-12~07-14. Pick 최초 생성이 07-21 이라
**자동화를 걸기 전 체크분**으로 보인다. ❓ 앱스토어 DB 자동화 유무는 미확인.

**⑬ Pick 이름 규약이 둘** — 자동화·07-28 관례는 **사람 이름**, `SampleProduct` 만 회사명.

## 4. 진단

꼬인 게 아니라 **층이 쌓였다.** 세 가지가 겹쳤다.

```
① 세대 누적      새 DB 를 만들 때마다 옛 것을 안 지웠다 (①)
② 주인이 둘      코드(~/kv)와 노션 자동화가 같은 DB 를 만지는데
                 서로의 존재를 어디에도 선언하지 않는다
③ 관계 0 · 복사만  한 사람이 4개 DB 에 다른 제목·다른 칸 수로 존재하는데 연결이 없다
                 "이 사람 어디까지 갔나"를 코드도 사람도 못 본다
```

②가 특히 위험하다. 2026-08-18 세션에서 *"체크박스를 읽는 코드가 없다"*고 단정했다가,
체크를 켜보고서야 자동화의 존재를 알았다. **코드로 Pick 생성을 만들면 자동화와 이중 생성된다** —
실제로 오늘 중복 10행이 생겨 5행을 아카이브했다.

## 5. 해결안

### 목표 경로 — 하나로 정하고 나머지는 동결

```
수집 → 채널 3DB       원본. 전량 착지. 코드가 쓴다
   ↓ `DB로 업데이트` ✅
   ⭐ Pick            사람이 고른 것 + 슬랙에 올릴 서식
   ↓ 만나기로 한 것만
   극초기 DB           회사 단위. 최종 성과 장부
```

경로 밖은 동결: **base(1,470행) · 테스트페이지(180행)**. 스레드는 스킬이 생길 때까지 보류.

### 순서

| # | 할 일 | 왜 이 순서인가 | 어디서 |
|---|---|---|---|
| 1 | **극초기로 가는 자동화를 끈다.** Pick 생성만 남긴다 | ⑥이 매 체크마다 dedup 대조원을 오염시킨다. 오늘만 5건 늘었다 | 노션 UI |
| 2 | 극초기 승격을 별도 단계로 뺀다 | 승격은 **행 복사가 아니라 단위 변환**(사람→회사). 회사명·한 줄 설명을 만들려면 판단이 필요해 자동화가 원리적으로 못 한다 | 코드 or 사람 |
| 3 | 오늘 찌꺼기 정리 — 극초기 5행 + `SampleProduct`/`Example Person B` 중복 | ⑥⑦ | 코드 |
| 4 | 대조 키를 **URL** 로 못 박는다 | 이름 대조는 `SampleProduct`/`Example Person B` 에서 이미 깨졌다 | 코드 |
| 5 | base · 테스트페이지 아카이브 or 제목에 `[동결 2026-07]` 표기 | ① 죽은 1,650행 | 노션 UI |
| 6 | `READ_ONLY` 3줄을 지우거나 실제로 쓴다 | ② 죽은 선언 | 코드 |
| 7 | 링크드 뷰 4본을 원본과 구별되게 표기 | 오늘 두 번 헤맸다 | 노션 UI |
| 8 | Pick `담은 날짜` 를 자동화가 채우게 | ⑩ | 노션 UI |
| 9 | 극초기 중복 6건 정리 (⑧⑨) | 대조원 위생 | 코드 |

**1번이 가장 급하다** — 적은 손으로 가장 큰 것을 막는다.

### 먼저 정해야 할 것 하나

**노션 자동화를 정본으로 둘 것인가, 코드로 옮길 것인가.**

```
자동화 유지   장점 이미 34번 작동했고 사람이 그 동작을 전제로 일한다. 크론 불필요
              단점 코드가 그 존재를 모른다. API 로 조회도 안 된다 → 항상 오늘 같은 사고 위험

코드 이관     장점 선언이 리포 안에 남고 검사를 붙일 수 있다
              단점 옮기는 동안 이중 생성. 자동화를 먼저 꺼야 한다
```

권장: **Pick 생성은 자동화 유지, 극초기 승격만 코드로.** 판단이 필요한 쪽만 코드가 가져간다.
