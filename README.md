# data 브랜치 — 앱스토어 순위 스냅샷

이 브랜치는 **코드가 아니라 데이터**를 담는다. `main` 과 히스토리를 공유하지 않는다(orphan).

## 왜 브랜치를 나눴나

계층 A(GitHub Actions)가 **매일** 스냅샷을 커밋한다. 연간 365개다.
`main` 에 쌓으면 `git log` 가 사실상 스냅샷 로그가 되어 코드 변경 이력을 못 찾는다.

## 왜 커밋하나

GitHub Actions 는 실행이 끝나면 러너가 삭제된다(ephemeral). 결과를 어딘가 남기지 않으면 증발한다.
저장소가 가장 싸다 — 무료이고, 이미 있고, 별도 자격증명이 필요 없다(열쇠 반출 금지 결정과 부합).

**부수 효과**: GitHub 무료 플랜은 저장소가 60일간 활동이 없으면 스케줄 워크플로를 조용히 끈다.
매일 커밋하는 것 자체가 "살아 있다"는 신호가 되어 그걸 막는다.

## 왜 날짜별로 쌓나 (append-only)

급상승·급하락은 **어제와 오늘의 차이(Δ)** 다. 덮어쓰면 어제가 사라져 계산이 불가능해진다.
그리고 지나간 날의 순위는 애플이 다시 알려주지 않는다 — **못 찍은 날은 영구 손실**이다.
실제로 2026-07-20~27 8일이 그렇게 비었다.

```
skills/net-sourcing/project/tools/sync_snapshots.py
```
